# Marsad v0.1.0

First release. Marsad (مرصد, *"observatory"*) is a read-only web dashboard that
shows what a Kubernetes cluster's network security posture actually is,
according to the policies you have declared — and for every edge it draws, it
can point at the exact rule that produced it.

It reads declared configuration, not live traffic. Every call to the Kubernetes
API is `get`, `list`, or `watch`.

## What is in it

**The evaluation core, `pkg/npeval`.** Which policies select a workload, what
the effective ingress and egress allow-sets are, whether the workload is
isolated, and whether a hypothetical connection would be allowed. Every answer
carries the identifiers of the rules that produced it. The package has no HTTP,
no UI and no client-go dependency — it evaluates an immutable snapshot a caller
has already fetched, which is what will let the same code back a CLI and a CI
check later.

**Two providers.** `networking.k8s.io/v1` NetworkPolicy in full: ipBlock,
selectors, ports, endPort, named ports, both policyTypes, and the nil-versus-
empty distinctions that are easy to get subtly wrong. And
`networking.k8s.aws/v1alpha1` ApplicationNetworkPolicy including `domainNames`
egress, detected through the discovery API — on a cluster without the CRD,
Marsad shows a badge saying domain policies are unavailable rather than
pretending the rules exist.

**A read-only API.** `/api/meta` for cluster capabilities, counts, and anything
Marsad could not read; `/api/namespaces`; `/api/graph`;
`/api/workloads/{ns}/{name}` for applied policies with YAML, effective rules and
isolation; `/api/simulate`; and `/api/stream`, a WebSocket that pushes a fresh
graph on every cluster change. Shared informers watch the cluster and the graph
is recomputed on change, never polled.

**The dashboard.** Namespaces as containers, workloads as cards, with each
destination's open ports listed on the card that accepts them. It aggregates at
the namespace level — the right view for a cluster you have not seen before —
and drills down to workloads on demand. Rendering is WebGL, so a cluster with
thousands of pods stays interactive.

**Simulation.** Ask whether one workload may reach another on a given port and
get the verdict plus the deciding rule, on both the egress and the ingress side.
Checking only one is how this goes wrong by hand.

**Unprotected workloads, called out.** A workload no policy selects is drawn in
the danger colour, and its card says "open from anything" or "open to anything"
rather than leaving you to infer it from edges that are not there.

**Honest uncertainty.** Some questions — does `*.s3.amazonaws.com` cover this IP
address? — need DNS resolution Marsad does not perform. Those results are marked
`Approximate` or `Undecidable` with the reason, never collapsed into a yes.

## Running it

```sh
helm install marsad oci://ghcr.io/fathiq/charts/marsad \
  --namespace marsad --create-namespace

kubectl -n marsad port-forward svc/marsad 8080:80
```

The chart is an OCI artifact, so there is no `helm repo add` step; Helm 3.8 or
newer. Plain manifests are in `deploy/` if you would rather not use Helm.

Images are on GHCR for `linux/amd64` and `linux/arm64`:

```sh
docker pull ghcr.io/fathiq/marsad:0.1.0
```

There is no Ingress and no authentication, by design. Reach it with
`port-forward`, which reuses the cluster's own authentication and authorization
instead of inventing a second, weaker one.

## Security posture

The ClusterRole grants `get`, `list` and `watch` and nothing else. There is no
write path in the codebase — not a disabled one, an absent one — and CI fails
the build if the chart's rendered ClusterRole contains any other verb. The image
is distroless and runs as non-root, with no shell and no package manager.

## Known limits

Cilium and Calico policies are not supported. `npeval.Provider` exists so they
can be added without touching the evaluator, but nothing implements it yet.
Graph exports and a findings engine are designed and not started.
